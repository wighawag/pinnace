---
title: decisions taken making eth.limo warming visible (status probe) and honest (warm outcomes)
date: 2026-07-27
status: open
---

Recorded while building `ethlimo-warming-status-visible-and-honest` (spec `sites-metadata-in-mfs`). Each is a choice a reviewer or another task could reasonably want to reverse, so it is written down rather than buried in the diff.

**1. `GatewayProbe` now takes a URL, not a cid.** The task allowed widening the existing probe rather than forking it, and there are now TWO things worth probing (`https://<cid>.ipfs.dweb.link/` and `https://<name>.limo/`). Widening keeps ONE injectable HTTP seam to fake, at the cost of a signature change to an EXPORTED type (`GatewayProbe`, `defaultGatewayProbe`) that a library consumer injecting its own probe must update. The URL is built inside the status core (`cidGatewayUrl`) so the probe stays a dumb `url -> status` call and the gateway hosts are still named in exactly one place. Alternative rejected: a second `EthLimoProbe` type, which doubles what every test and production wiring must inject.

**2. `<name>.limo` is spelled ONCE, in `site/site-wrapper.ts` (`ethLimoUrl`).** The warmer (`node warm`) and the prober (`status`) must not disagree about the URL, and the module that owns `resolveEnsNameToWarm` (which produces the name) is its natural home; putting it in the status core would have made `node-commands` import `status-report`, which imports `node-commands` back. The dashboard renderer deliberately still builds its own link: it URI-encodes the name into an `href` and stays a pure, import-free view. Touches: `status-report.ts`, `node-commands.ts`, and `status-html.ts` (which keeps its own `ETH_LIMO_HOST`).

**3. `ethLimoServes` is THREE-valued (absent = not applicable), not an enum.** `true` served, `false` probed and did not, ABSENT there was no `<name>.limo` to probe (an `ensName: ""` opt-out, or a non-`.eth` id). This mirrors the repo's existing three-valued `ensName`/`ensNameToWarm` discipline and keeps the JSON payload key-free for a site with nothing to probe, instead of introducing a new status vocabulary (`serving`/`not-serving`/`not-applicable`) that would have to be kept in sync with the boolean `announced`/`gatewayServes` columns beside it. Consequence for the CLI/dashboard: the not-applicable case prints `ethLimoServes=n/a` and renders as no verdict at all (never a red `no`).

**4. The `status: 'ok' | 'unverified'` token stays about the CID.** An eth.limo failure does NOT flip a site to `unverified`. That token has meant "announced AND served" to existing consumers of `status.json`, and silently widening it would re-mean a shipped field; the eth.limo verdict is reported in its own fields instead. Reversible if the dashboard later wants one roll-up health token, but that should be an explicit decision, not a side effect of this task.

**5. `warm` outcome vocabulary: `warmed` / `partly-warmed` / `warm-failed` / `nothing-to-warm`.** Kebab-case, like the existing `re-announced` / `no-record` / `ipfs-mode` tokens. `partly-warmed` is what makes the interesting `.eth` case visible (CID gateways hot, `<name>.limo` cold), and `SiteOutcome.ethLimoWarmed` pinpoints WHICH half failed, so the token summarises without needing a token per combination. `nothing-to-warm` is the fourth because a site with no gateways configured and no ENS name attempted nothing, and reporting `warmed` there would be the same lie this task removes. It is USER-VISIBLE: `pinnace node warm` prints the token per site.

**6. A non-2xx warm answer counts as a FAILED warm, not just a throw.** The mis-named test this task fixed only exercised a throwing gateway, but a cold gateway usually ANSWERS (504/404); counting that as success would leave the same lie in place for the most common real failure. The 2xx test matches the `status` core's `servesStatus` predicate; the two are deliberately duplicated one line each side of the seam rather than importing across it (which would make `node-commands` -> `status-report` -> `node-commands` circular). The error policy is UNCHANGED: nothing new throws.
