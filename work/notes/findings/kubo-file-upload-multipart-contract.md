## The contract

Kubo's file-upload RPC endpoints (`add`, `dag/import`, `key/import`) do NOT accept a raw request body. They require a `multipart/form-data` body carrying the payload as a **file part**, and reject a raw `application/octet-stream` body with `400 file argument 'path' is required` (observed live against kubo v0.38.1).

## Field name is `file` (not the doc's "argument" name)

The RPC reference lists an internal Go *argument* name per endpoint under "Request Body":

- `add`: `Argument path is of file type.`
- `dag/import`: `Argument path is of file type.`
- `key/import`: `Argument key is of file type.`

That internal name is NOT the multipart field name. Every endpoint's cURL example uploads the file under the field name `file`:

- `curl -X POST -F file=@myfile ".../api/v0/add?..."`
- `curl -X POST -F file=@myfile ".../api/v0/dag/import?pin-roots=..."`
- `curl -X POST -F file=@myfile ".../api/v0/key/import?arg=<name>&..."`

The reference prototype (`~/searches/ipfs-hetzner/deploy-car.mjs`, `upload-folder.mjs`, `browser-upload.html`) and the live `curl -F file=@site.car .../dag/import?pin-roots=true` workaround all confirm the field name is `file` for all three. Kubo matches the file part positionally / by file-type, so `file` works regardless of the internal arg name.

## How to send it (Node/`fetch`)

Build a `FormData`, append the bytes as a `Blob` under `file`, and pass it as the fetch body WITHOUT hand-setting `content-type`. `fetch` serialises the `FormData` and sets `content-type: multipart/form-data; boundary=…` itself. Hand-setting the content-type omits/overrides the boundary and breaks the request.

Query params (`dag/import?pin-roots=true`, `key/import?arg=<name>`, `add?...`) and the `Authorization: Bearer <token>` header are unchanged by the encoding: only the body/content-type handling differs.

## Where this is used / guarded

- Production: `packages/pinnace/src/rpc/kubo-rpc-client.ts` (`add`, `dagImport`, `keyImport` route through `fileUpload`).
- Guarded without a live daemon by `MockKuboApi` (`packages/pinnace/src/rpc/mock-kubo.ts`), which now derives `multipart/form-data` + extracts file parts from a `FormData` body, and by the "file-upload endpoints send multipart/form-data" tests in `packages/pinnace/test/rpc/kubo-rpc-client.test.ts`.
