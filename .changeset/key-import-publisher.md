Import the derived per-site IPNS key into the PUBLISHER node's keystore (`serializeIpnsKeyForImport` / `importIpnsKeyIntoPublisher`). The derived ed25519 keypair is serialized into the `libp2p-protobuf-cleartext` `PrivateKey` form `ipfs key import` expects (`0x08 0x01 0x12 0x40` + the 64-byte seed||pubkey `Data`) and POSTed via Kubo `key/import` under the site key name. Import is publisher-only: a `replica` import is REFUSED (`KeyImportRoleError`) with no RPC issued at all, so replicas stay keyless. The client supplies key MATERIAL only; the node signs IPNS records itself via `name/publish` (a separate concern). Tests at the mock Kubo RPC seam pin the serialized bytes (from the golden-vector key), assert the key lands via `key/import` on the publisher with the bearer token, that a replica is refused touching the node not at all, and that the import path issues ONLY `key/import` (no `name/publish`/`routing/put`) and reaches for no client-side signing primitive. ADR-0003 records the load-bearing invariant that client-side key derivation is NOT client-side record signing (spec Out of Scope C-1): the client hands over material, the node is the sole record signer and sequence-number writer.
