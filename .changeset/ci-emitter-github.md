Add the `install-ci` CI emitter behind a `CIProvider` seam, with GitHub Actions as the first (v1-only) implementation. `emitCi({system, buildCommand, outputDir, ...})` is a PURE core function: it returns the deploy workflow file (path + contents) plus the required repo secrets/vars report, so the CLI wrapper writes the file and prints the report. The emitted GitHub Actions workflow ports the reference Action's shape (checkout, setup-node, install, build, a deploy step reading the multi-node env contract, a run summary), with two corrections vs the reference: the deploy step invokes `pinnace deploy` (this tool now owns deploy, no bash/TS drift) and the env carries the multi-node + per-site-mode semantics the deploy core enforces. The report splits `IPFS_TOKEN` (secret, comma-separated tokens, publisher first) from the repo variables `IPFS_API` (comma-separated endpoints, publisher first), `SITE_NAME`, and `SITE_MODE` (ipfs | ipns, default ipns). Multiple nodes serve the same CID; in ipns mode the publisher publishes the signed record and replicas mirror it. Snapshot-locked workflow + a secrets/vars-report assertion. Other CI systems are Out of Scope but slot in behind the same seam later.
