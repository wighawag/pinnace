Add the publisher / keyless-replica IPNS record machinery (spec C-2 model; user stories 12, 13, 14) as a dedicated core module (`src/publisher/record-sequence.ts`), so a shared IPNS name stays reachable with a grace window even if the publisher dies. Exactly ONE publisher per name refreshes the record's validity by re-SIGNING it (`name/publish`, ~72h lifetime / ~1h ttl) and EXPORTS the raw signed record (`routing/get`) plus its ipns id to a records dir (`republishAndExport`). Keyless REPLICAS fetch the publisher's exported record, re-announce it (`routing/put`), and FALL BACK to their last cached record when the publisher endpoint is unreachable (`mirrorAndReannounce`) — they NEVER sign (no `name/publish`), upholding the "no client-side record signing" invariant (spec Out of Scope C-1, ADR-0003). The record sequence has a SINGLE implementation (ADR-0002): the on-box `pinnace node republish|mirror` verbs delegate to this core through their `NodeCommandOps` seam via `makeRepublishOp`/`makeMirrorOp` (mirroring how `status-report` supplies the `status` op), so client and box run the same code with no bash/TS drift. `promoteReplicaToPublisher` (story 14) recovers a name without content downtime by reusing the `key-import-publisher` seam to import the derived key and flip the role to publisher, within the record's validity window. Behaviour ported (not copied) from the reference cloud-init scripts `ipfs-ipns-publish.sh` / `ipfs-ipns-mirror.sh`. Proven mock-green at the mock Kubo RPC boundary + a fake publisher endpoint (the full export -> fetch -> `routing/put` -> fallback-to-cache sequence, plus replica-never-signs); a self-skipping live failover smoke test (`record-sequence.live.test.ts`) is shipped opt-in via env for the `verify-ipns-failover-live` follow-up task and touches no real infra by default.
