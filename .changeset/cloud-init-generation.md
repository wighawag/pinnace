Generate a Kubo node's cloud-init YAML programmatically in TypeScript behind a `HostProvider` seam, with `hetzner` as the first implementation (`provision(input)` returns a ready-to-paste `cloud-init.yaml` from a host/site/role config). This replaces the superseded shell `sed`-template prototype. Only host-specific provisioning lives behind the seam; deploy/publish/status stay host-agnostic (they speak only Kubo RPC), so a new host slots in later without touching them (user story 21). The emitted YAML encodes the hardened-node invariants ported (not copied) from the reference: Kubo as a hardened systemd unit; ufw opens 4001 TCP+UDP + 80/443 but NEVER 5001/8080 raw (API + gateway bound to localhost); discoverability (`Routing.AcceleratedDHTClient` + `Routing.Type auto` + `Reprovider.Interval`/`Strategy`); Caddy HTTPS + bearer API reverse proxy. Per ADR-0002, the cloud-init does NOT bake the reference's bash loop scripts: it INSTALLS the `pinnace` binary on the box and schedules `pinnace node republish|mirror|warm|status` on role-gated systemd timers, with `NODE_ROLE` written from config so republish/mirror self-gate (all timers safe on every box). Snapshot + invariant tests lock the emitted YAML and the security properties.
