Add the `status` core operation (spec user story 18): pinnace's discoverability verification surface. For every site auto-discovered from MFS `/sites/*` (over the Kubo RPC seam) it reports four fields so an operator can confirm a deploy landed everywhere: the current CID (`files/stat`), the IPNS id (from `key/list` if a same-named key exists, else absent for ipfs-mode sites), whether the NETWORK announces this node for the CID (an external delegated-routing providers lookup at `delegated-ipfs.dev` whose `.Providers[].ID` list contains this node's PeerID from `id`), and whether a COLD public gateway serves it (a `dweb.link` range-request HTTP probe). The two external checks are INJECTABLE (`ProvidersLookup`, `GatewayProbe`) so tests run against a fake HTTP layer and never the live network; production supplies `fetch`-backed defaults. Both checks fail SOFT: a routing error reports `announced=false` and a gateway error reports `gatewayServes=false`, never a throw, so one flaky endpoint cannot fail the whole report. `makeStatusOp` adapts this core into the on-box `node status` verb's injectable `NodeCommandOps.status` seam. The check shapes are ported (not copied) from the reference prototype `status.sh`. Tested entirely against the mock Kubo API plus the two injected fakes.
