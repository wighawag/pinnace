Add a global `--config <path>` flag to the `pinnace` CLI so the config file can live anywhere (e.g. `runbook/pinnace.json`), not just `./pinnace.json`. `--config` is a GLOBAL flag consumed in `run()` before the command and stripped from the per-verb argv (so a verb parser never mis-reads it), threaded into config loading through the existing injectable `RunContext.loadConfigFile` seam (whose signature widens to `(path?: string) => PinnaceConfigFile`). Default behaviour is UNCHANGED: with no `--config`, `./pinnace.json` is read if present and its ABSENCE stays a benign empty config (a config file is optional). But an EXPLICITLY named `--config <path>` that is missing / unreadable / invalid JSON FAILS LOUD (a `ConfigLoadError` naming the path, exit 1) rather than silently resolving to an empty config, because an operator who named a file has claimed it exists and a typo'd path would otherwise surface as confusing downstream "no hosts configured" errors. Precedence is unchanged (CLI arg > env > file); `--config` only chooses WHICH file is the file layer, and no secret gains a file path (master/token stay env-only). Tests drive the flag through the injectable loader and real temp files, isolating the operator's real `./pinnace.json` and real env.
