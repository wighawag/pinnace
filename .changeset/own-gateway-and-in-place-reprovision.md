Two provisioning additions: an optional self-hosted PATH gateway per node, and a way to apply provisioning changes to a box that is already running.

**`provision --gateway-domain <d>`** exposes the node's own Kubo gateway at `https://<d>/ipfs/<cid>/` and `/ipns/<name>/`, so you can view your sites on your own box instead of through a third party. Caddy gets a third vhost that forwards ONLY `/ipfs/*` and `/ipns/*` to the localhost gateway (anything else is a 404 at Caddy, which also keeps Kubo's routing API on that port private), and Kubo runs with `Gateway.NoFetch=true`, so the gateway serves only content the node already holds and can never act as an open proxy for arbitrary CIDs. `GATEWAY_DOMAIN` is written to the box env file and the on-box dashboard gains an `own gateway` field per site linking the cid and the ipns name through it. The `gateway` health indicator is unchanged and keeps probing a PUBLIC gateway. The hostname must be a bare hostname distinct from the API and dashboard domains (refused otherwise), so hosted site JavaScript can never share an origin with the status page. Without the flag the emitted cloud-init is byte-identical to before.

**`provision --in-place`** prints a root bash script instead of the cloud-init. cloud-init only runs at first boot, so until now a changed input could only reach a box by recreating it. The script rewrites the same files the cloud-init writes (both are now rendered from one definition, so they cannot drift), then re-applies the Kubo setup with the daemon briefly stopped (a trap always restarts it), rewrites the Caddyfile, reinstalls the pinned agent and re-enables the timers. Pins, MFS sites, keys, the firewall and packages are untouched. `PINNACE_DRY_RUN=1` previews the env diff (bearer token masked) and the changed files, and it refuses to change `NODE_ROLE` or `RPC_BEARER_TOKEN` unless `PINNACE_ALLOW_ROLE_CHANGE=1` / `PINNACE_ALLOW_TOKEN_CHANGE=1` is set.

The Kubo install step no longer depends on one download host: it skips the download when the pinned version is already installed (so an in-place reprovision never re-fetches it), and otherwise tries dist.ipfs.tech then the GitHub release, each with a bounded timeout. A live reprovision hit a dist.ipfs.tech outage that hung the old single `curl` for five minutes.

Library: `ProvisionInput.gatewayDomain`, `ProvisionResult.reprovisionScript`, `NodeCommandContext.gatewayDomain` and `RenderStatusHtmlOptions.gatewayDomain` are new. `ProvisionResult` gaining a required field is a type-level change for anyone who constructs one (e.g. a test double for `provision`).
