Add the host-agnostic **deploy** core operation (`deploy`; spec user stories 4, 6, 7): build a site's CAR ONCE (via the `car-build` seam), then fan out across every configured node (each with its OWN bearer token) so all nodes serve the IDENTICAL CID with no single point of failure. Per node the flow is `dag/import?pin-roots=true` (import + pin) then MFS placement at `/sites/<name>` (mkdir parents / rm old / cp `/ipfs/<cid>`, reusing the exported `placeInMfs` helper so warm/republish/status auto-discover the site). The per-site **mode branch** is wired here: `ipfs` mode does land+pin+MFS ONLY (no key, no publish), while `ipns` mode ADDS the publish path (`key/list` then `name/publish`) and ONLY on a publisher target whose publish switch is not disabled; a `replica` (or a publish-disabled publisher, the prototype's `PUBLISH_IPNS=0`) lands content but NEVER signs. Deploy assumes the publisher already holds the site key (looked up via `key/list`, imported by the sibling `key-import-publisher` task) and does NOT `key/gen`/`key/import`; if no key exists yet it lands content without signing rather than provisioning one. Fan-out mirrors the reference prototype's `Promise.allSettled` semantics: a node that fails is reported per-node (`DeployResult.failed`) without sinking the others, and a non-empty subset succeeding is still an overall `success` (some-nodes-up). Behaviour ported (not copied) from `~/searches/ipfs-hetzner/deploy-car.mjs`. Test-first, driven entirely through the recording mock Kubo API (each node its own baseUrl + token + recorded requests, no live daemon): assertions pin the exact per-mode call SEQUENCE for both modes, the same-CAR/same-CID multi-target fan-out with per-token isolation, that a replica never publishes, and the partial-failure-is-still-success behaviour.
